# The first pictures: recipe

`public/first/` holds what the page paints before the app has drawn anything: one still of every season on every screen shape a still is drawn for, each as AVIF and as WebP, and `stills.json`, the record of what each was drawn from. A visitor's browser fetches one of them. Nothing in the folder is made by hand: every file is written by one tool from the built site, and the same tool writes the table in `index.html` (between `/*first:begin*/` and `/*first:end*/`) that names the stills and says where each goes.

The stills belong to one build. A still is the app's own first picture, so every still is drawn again whenever the engine hash moves (`tools/lib/hashes.mjs`, `engineHash`: any change of a file under `src/` or `config/`, of `package-lock.json`, or of `cut/AUDIO-MAP.json` once there is one), also when the change moves no pixel. `public/first/stills.json` records the hash: `controls.from` is the engine hash the controls were measured on, and `stills.<season>-<screen>.from` is the first 16 hex digits of the SHA-256 of that hash together with the lists of the built web files of `shared` and of the season, each file with its own hash (`dist/assets/index.json`, `sets.web`). `node tools/poster.mjs --check` holds both against today's build and fails when they are another's.

## public/first/
Made by: `tools/poster.mjs` (rule version `CODER = 3`) with `tools/lib/page.mjs`, `tools/lib/browser.mjs` and `tools/lib/hashes.mjs`, in Node 20.20.2; drawn in the pinned browser of `tools/browser.json` (version 147.0.7727.15, build `chromium-1217`, headless, through playwright-core 1.59.0) with the software renderer that file names (lavapipe of Mesa 26.0.8 behind ANGLE's Vulkan back end); the framing read from `src/app/framing.ts` through vite 8.3.8; the pictures coded through sharp 0.35.5 (libvips 8.18.7, libheif 1.23.5 with aom 3.15.1 for AVIF, libwebp 1.6.0)
From: the built site `dist/` of the app as main has it at 4af03199 (merged into `agent/p6-first`; the engine hash and the web files are the ones `stills.json` records), with the web set of `public/assets/` (`assets-src/web-pack/RECIPE.md`). For each season of `seasons` in `config/showcase.json` the page is opened as a visitor opens it, at `?season=<season>&quality=high` (the first level of `live.quality`, the one the app draws its first frames at), at rest: no shake, no change of season, the interface in the page and measured but out of sight. The frame kept is the one the app calls its first picture (`data-first-picture` on the document). The same page is then given each other size and draws a frame at it. The sizes: `hd` 1920 x 1080 (`formats.hd`) and `wide` 2560 x 1080 at one pixel a point, `tablet` 1024 x 1366 (`formats.tablet`) at 1.5, `phone` 390 x 844 (`formats.phone`), `phone750` 390 x 750, `phone667` 390 x 667, `phone590` 390 x 590, `square` 719 x 720, `low` 719 x 481 and `mid` 719 x 600 at two. `defaultSeason` goes into the table as the season the page shows when the address names none.
Prompt or command: four commands, in this order:
- `npm run build` (the stills are drawn from `dist/`)
- `node tools/poster.mjs` (measures the controls on today's build, draws every still that is not of today's build, codes it, and writes `public/first/<season>-<screen>.avif` and `.webp`, `public/first/stills.json` and the table in `index.html`)
- `npm run build` (the table is part of the page)
- `node tools/poster.mjs --check` (draws nothing; must print `poster: pass`, and exits 1 when a still, the controls or the table are not today's)
- Options of the second command: `--season winter,fall` and `--shape phone,wide` draw those again whatever they were drawn from, with `--only` nothing but those; `--keep` keeps the stills of another build while the framing is theirs, for a change known to move no pixel.
- The coding: a frame is grabbed as PNG at the pixels of its screen. AVIF is `sharp.avif({ quality, effort, chromaSubsampling: '4:2:0' })` under 60,000 bytes, WebP is `sharp.webp({ quality, effort, smartSubsample: true })` under 90,000 bytes (`BUDGET`). The quality is the highest that fits, searched between 34 and 70 for AVIF (at effort 2, then climbed at effort 4, which is the file) and between 46 and 86 for WebP (effort 6); a still that does not fit at the lowest is resized by 0.8 a side with the lanczos3 kernel, down to 0.4, until it does. The page lays it at the size it was drawn for.
Takes: 1 for each season and screen, the frame the app calls its first picture: 40 stills in two codings, 80 files, and `stills.json`. The command gives the same bytes again on the machine it ran on: on 2026-11-26 all 40 stills were drawn twice, on two builds of the app in a row (main at 0f3e0973 and at 933e05f7, with a change of `src/core/materials.ts` between them), and the 80 files of the second run are the 80 of the first, byte for byte; the 56 files of the seven screens the repository held before came out both times as they were committed.
Why this one: a still that is the app's own first picture for the visitor's screen has the camera, the light and the moment the live picture has when it comes in over it, so the glass does not move at the takeover (0 to 1 px on the screens looked at); a picture drawn by hand or by another path would. Ten screens because a narrow window moves the camera with every change of shape. AVIF is the lightest coding a browser decodes with no code of ours, WebP is for the browsers without it.
