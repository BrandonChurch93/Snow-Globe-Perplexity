You own: `tools/measure.mjs`, `tools/pack.mjs`, `tools/lib/measures.mjs`.

- `tools/measure.mjs --unit ID [--only M1,M4] [--tier T]`: M1 to M6 exactly as the table defines them, for the judged stills of that unit (`window.showcase.dev.judged()` gives the list with each entry's unit and kind). The page gives what each needs, listed in `tools/README.md`: `dev.sanity()` and `dev.inside()` after a picture, `dev.framing(camera)`, the `ids`, `texels` and `cover` views with their encodings, `dev.renderShakeMoment(shot, at, tier)` for M4 (`swap`) and M5 (`settle`), with `test` as the shot for the unit `winter`. M3 compares high frequency energy on the base and on the miniature with the matching regions of the approved image at the same size: `tools/lib/compose.mjs` already places a still and its approved image on the same globe circle, so use its placement. Results go to `out/work/measure/<unit>.json` and a readable `<unit>.md`, one line per measure and still: pass or fail, the number, the threshold's config key. The command exits 0 whatever the result: a red measure is an issue for the round, not an error.
- `tools/pack.mjs --phase N --round R --unit ID`: the critic packs of "Packs", for every critic role the round uses. A pack is a folder `out/work/packs/round-RRR/<role>/` holding at most `critics.maxFilesPerMessage` files with neutral names (`set-A-01.jpg` and so on, never a word such as render, target, approved, generated, final or a technique's name), every picture inside the limits from `limits()` in `tools/lib/compose.mjs`, plus a `key.json` written outside the pack folder that says what each file is. A pack is deterministic: the same inputs give the same files.
